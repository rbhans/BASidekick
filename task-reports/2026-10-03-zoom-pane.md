# Zoom Pane

October 3, 2026. The user scrapped the whiteboard idea: "just do a pane that's as native as can be, like other panes, where whatever you put on the pane you can zoom/pan about and have a minimap". The unbuilt whiteboard files and registrations were removed.

## Design

Shaped like `bajaui:ScrollPane` / `bajaui:TransformPane`: one `content` slot (default `BNullWidget`), shown at its preferred size (a CanvasPane's View Size). The viewport adds zoom, pan, controls and a minimap.

SDK evidence (N4.15.3.28 `docSource-doc.jar`, `bajaui-wb.jar`, `bajaui-ux.jar`):

- **Transform:** `BCanvasPane` applies its scale in `paint` and inverts it in `childAt` / `translateToChild` / `translateFromChild`. `pxEditor-wb` has no CanvasPane-specific code, so these generic hooks are what the editor uses.
- **Input routing:** `com.tridium.ui.awt.MouseManager` targets the deepest widget and walks up only while `receiveInputEvents()` is false.
  - `BLabel` and `BShape` take input only with bindings; `BBoundLabel` and `BAbstractButton` always take input.
  - Panes take input, so a CanvasPane would swallow every drag. `BZoomPane.childAt` therefore routes into the content only where `descendentAt` finds a non-pane widget that takes input. Elsewhere the Zoom Pane takes the event and pans or zooms. The PX editor routes normally.
- **UX:** `rc/ux/TransformPane.js` renders `spandrelSrc: model.get('content')` with a `NullWidget` default from `$uxModelDefaults`; `ZoomPane.js` does the same.

## Files

| Part | File | Role |
|---|---|---|
| wb | `ui/BZoomPane.java` | Pane: content layout, view transform and its inverse, scroll-pane clamping, start fitted / 100%, input routing, painted thumbnail minimap, controls, wheel/drag/double-click. |
| wb | `ui/BHxZoomPane.java` | Hx agent: background, hidden marker, loads `zoompane.js`. Mouse events are not forwarded to the server. |
| ux | `ux/BUxZoomPane.java`, `rc/widgets/ZoomPane.js` | UX agent. |
| ux | `rc/zoompane/zoompane.js` | Shared browser core. Drag pans after a 4px threshold, swallows the click that follows a pan, and never hijacks form fields. The minimap is a copy of the content with ids removed. |
| wb | `module.palette` | `Layout > Zoom Pane`, 960×540, with a 1920×1080 CanvasPane already in Content. |

## Verification

- `javac` against the SDK jars (scratch; not a module build): `BZoomPane`, `BHxZoomPane` and `BUxZoomPane` compile. Reflective slot check: 8 properties, each with a public getter and a matching void setter. Control: `BLinkPlanner`.
- Partial static check: 36 types, 87 slot contracts, XML/palette/JS pass.
- `zoompane.js` in Chromium with an Hx-shaped DOM (900×500 pane, 1920×1080 content):
  - opens fitted at 46.3%, centered;
  - wheel zoom keeps the point under the cursor fixed;
  - dragging on the graphic pans exactly with the pointer;
  - a plain click reaches the button; a drag starting on the button pans and its click is swallowed;
  - panning past the edges stops at the content's corner;
  - Fit restores 46%; the minimap frame tracks the view, and the minimap copy has no duplicate ids.
- Fixed during the work: removing the whiteboard registrations left an orphaned `</agent></type>` in `basidekick-wb/module-include.xml` (the removal regex stopped at the first `/>`). The static check's XML parse caught it.
- **Not run:** Gradle build, Workbench, Hx, UX Media, PX editor behavior.

## Known limits

- In Workbench the wheel over an interactive widget (bound label, button) goes to that widget, as with ScrollPane; zoom from anywhere else.
- In the browser, the minimap copy refreshes every 10 s and on settings changes; `<canvas>` content appears blank in it.
